# Repo Adapter scope — v0.2.1

2026-10-12 更新。已交付原创 MIT agent skill、能力地图模板、源码检查示例与站内下载入口。状态是可使用的指令包，已经完成有限独立任务检查；不同平台/模型的系统评测尚未完成。

## 要解决的问题

用户找到一个或多个 repo 后，需要知道某项功能在哪里、哪些部分能用、怎样接入自己的产品。一次分析可以比较替代方案，也可以拆分职责；不会默认把所有 repo 拼在一起。

## 输入契约

| 输入 | 内容 |
| --- | --- |
| 目标行为 | 谁使用、输入什么、产生什么、怎样算完成。 |
| 来源 | repo 地址或本地路径，固定 commit；无法固定时记录原因。 |
| 目标项目 | 已有代码、技术栈、平台、接口与可接受依赖。 |
| 改造方式 | extraction、refactor 或 redesign。 |
| 教育要求 | 尝试与提示的顺序、反馈、语言、无障碍、教师检查、资料出处。 |
| 工作边界 | 可读与可改范围、预算、需要交计划还是实施。 |

已有信息直接使用。缺少可合理假设的细节时声明假设；只有缺失信息影响关键选择或授权范围时才提问。

## 执行方法

1. 读版本、文档、相关入口与测试，建立有限分析范围。
2. 将需求拆成可验收能力，按输入、输出、状态和数据流搜索实现。
3. 深入有关文件与调用关系，记录文件、符号、版本与覆盖范围；区分源码观察、推断与运行结果。
4. 逐项决定直接复用、写 adapter、局部修改、重写或放弃，并说明理由。
5. 如需组合多个 repo，检查数据结构、权限、状态、依赖、平台与重复职责。
6. 交付能力地图、接口契约、改造顺序与验收；用户要求实施时按边界继续。

默认按需读源码，不把完整源码树作为必需上下文。搜索没找到只能说明已检查范围内没找到，不能据此断言整个项目没有该能力。

## 输出契约

- **CapabilityMap**：requirement、repository、commit、file/symbol evidence、input/output、dependencies、state、reuse decision、unknowns。
- **AdaptationPlan**：保留与改变的行为、接口连接、顺序、替代方案、验收与未验证项。
- **来源与复用记录**：代码、数据、文档等具体组件的使用条件，不能用仓库根许可概括所有资源。

包内 `references/handoff.md` 提供交付模板。输出可以是 Markdown 与 JSON，便于用户交给自己的 coding agent。

## Refactor 与 Redesign

| 模式 | 必须说明 |
| --- | --- |
| Refactor | 外部行为和接口基线；结构改变前后的有意义检查；允许改变的范围。 |
| Redesign | 哪些行为保留、哪些行为改变；新的学习流程与验收。 |

例如将立即显示答案改为先尝试、再逐层提示，属于 redesign。不能将这一行为变化标为纯 refactor。

## MVP 验证与样例

已检查本站 `public/tools/fraction-bars.html` 的固定版本与内容哈希，定位 `updateDisplay`、`showFeedback`，输出 [能力地图样例](repo-adapter-example.json)。样例识别立即显示反馈的行为，以及相同分母且分子相等时解释需要检查的问题。它给出改造计划，未改动原工具，未声称提示改造已运行。

后续行为评测任务：

- 单 repo：分数比较 → 分层提示，核对相等、大小关系、题目切换与键盘操作。
- 多 repo 替代比较：选择文档解析实现与检索实现，先判断是否确有必要组合。
- 不适用边界：源码不可得或需要发行物动态证据时，说明证据缺口，按需评估 REA。

第一项已完成源码分析与计划样例；三项实施行为评测尚未完成。

## 范围与完成标准

本 skill 提供源码能力适配方法，不托管用户代码，不默认运行陌生项目，不执行外部发布。REA 是发行物逆向的可选补充，普通源码分析不依赖它。

完成意味着证据能定位到读过的版本，每个复用决定有理由，关键未知项明确，计划有可检查验收。一次分析通过不代表改造运行、组合兼容或教学效果通过。

## 分发与维护

解压 `edu-repo-adapter.zip` 后按当前 agent 的 skill 目录规则使用。公开核心为 MIT；第三方材料维持各自条件。维护订阅未来可提供更新后的能力索引、适配模板与变更复查，当前没有收费服务。

## v0.2.1 迭代交付

完整指令入口、按需参考资料、机器可读模板、无第三方依赖的 Python 证据工具与 Codex UI metadata 已加入。保留自动发现，不依赖另装第三方 skill。测试数据、独立任务产物与回归测试保留在 `tests/skill-evals/`；脚本测试不等同于 agent 任务或教学效果评测。

`repo_evidence.py inventory` 记录有界搜索范围、文件哈希、引用行、跳过内容与截断；`verify` 核对交付的文件、引用、哈希和检查记录。源码无 Git 时保留未确认版本；工作区字节与 commit 分开。纯 refactor 保留现有外部行为，并把既有测试失败与本次回归分开。多 repo 接口显式处理页码、数据形状、文本渲染及组件条件。

最新任务与实际结果见 [迭代验证报告](skill-iterations-2026-10-12.md)。此前的未评测状态是 v0.1.0 的历史记录；这轮完成有限本地测试，不宣称跨模型性能提升。
