# Build brief

1. User goal, builder/end-user roles, required vs optional constraints and assumptions.
2. First useful artifact and learning interaction: attempt → hint/feedback → next action.
3. Selected resources: source/version, role, observed conditions, evidence, substitutes.
4. Interfaces: inputs/outputs, transformations, dependencies, persistence and missing contracts.
5. Sequence: one runnable interaction first, then data/model integration only if needed.
6. Acceptance: observable product behavior, functional checks and a separate learning/research task.
7. Open questions and the exact next verification action.

Example: a math practice page starts with three owned problems and two staged hints. It can run as HTML without a model API. A PDF import step is optional and needs a format/citation contract; a complete tutoring framework is an alternative, not automatically another required dependency.
