## Reference and content ownership

The Atlas interaction work inspected `AI_Literacy/web/src/atlas/MapCanvas.tsx` and `evidence.ts` and the user's screenshots. It reuses the ideas of a zoomable map and behavior-based progress, not that project's source or knowledge data. The user-provided `AI_Literacy/web/.claude/skills/teachable-figures/SKILL.md` informed the teaching-figure design. VibeHub courses and Datawhale Easy-Vibe informed course organization; course prose and graphics are authored for this site. See `course-editorial-notes-2026-09-20.md` for curriculum structure and review boundaries.

Research stays in the versioned `public/learning-sciences/0.2.0/rack.json`. Course sequencing, Chinese editorial explanations, resource associations and user records are separate layers linked by stable IDs. A `requires` relation describes a research/implementation condition, not an automatic course prerequisite. A resource connection describes a design relationship, not proven learning effectiveness.

The resource gallery reads the compact Chinese labels rather than bundling the full research rack. Atlas receives course summaries/counts rather than the full curriculum. Individual lessons receive only their own course and the progress-ID registry.

## Scope boundaries

This is a local preview. Additional library items require individual review before publication. Learning and practice records are stored in the current browser; opening a page does not prove mastery. No model service, account system, cross-device storage or backend has been introduced. Radar refresh updates the site's public snapshot, not the standalone Radar database/deployment; its refresh script runs only when deliberately invoked.

## September 20 — second revision pass

The owner reviewed the first pass and reported that it showed a lot without answering why any of the three audiences should care, that the landing page was
overwhelming, and that every page except `/directory` felt flat. This pass answers those three points.

- The landing page now opens on a vision band rather than a feature: the page's only `h1` is 「会用 AI 的人，第一次能把自己想到的做出来。」, followed by four
  named problems worth solving. The owner's framing was that a brick and a hammer are not enough — the visitor has to be shown the nail.
- A 「哪一个是你？」 section follows, with three audiences (老师 · 教研 / 构建者 · 开发者 / 家长 · 自学者). Each states that person's stuck sentence in the first
  person and links to one concrete first step. `/use` and `/build` carry the same three-audience band with their own destinations.
- The redundant three-link value strip was removed and the two tail sections merged, so the four-purpose demonstration now follows the audience choice
  instead of opening the page.
- `app/globals.css` gained a shared depth vocabulary — `--lift-1..4`, `--rim`, `--carve`, `--press`, `--surface-1/2/3`, `--surface-deep`, `--grain`, and the
  utility classes `.lift`, `.well`, `.deep`, `.stack`. Every section page uses it and each has exactly one `.deep` band. The owner asked about three.js; no
  dependency was added. Depth comes from layered shadows, gradient surfaces, 1px light rims and CSS transforms, following `.radar-hero-shelf`, which the
  owner named as the one composition that already read correctly.
- `/learn` now states plainly on the first screen that these are free courses that can be started immediately, with one primary action pointing at a named
  first lesson and one escape hatch to `/use`.
- `/atlas` opens with what it is for — 「把一条学习原理，连到你能改的那一处设计。」 — with the scenario entries and the map both inside the first screen. Atlas
  state, URL handling, graph rendering, progress records and every source caveat are unchanged.
- `/changelog` was rebuilt as reverse-chronological dated releases with a status rail, one category tag and one plain-language headline per entry. The
  「未来探索」 section for EduOS, Loom and Working Graph is retained.
- Mixed Chinese/English user-facing strings were corrected: Chinese name first, English term in a labelled secondary position. Research data
  (`public/learning-sciences/**`, `app/content/atlas-zh.ts`) is untouched.

Validation after this pass: `tsc --noEmit` clean, ESLint clean, all seven test suites pass, `npm run build` generates 25/25 static pages, and an HTTP smoke
check returned 200 for every route with `/learn/git-first-checkpoint` at 308 and `/updates` at 307. Not verified visually: the Chrome extension could not
load the local preview in this session, so layout and contrast were checked from rendered HTML, emitted CSS and computed contrast ratios rather than by eye.
Nothing was committed, pushed or deployed.
