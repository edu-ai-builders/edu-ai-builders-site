# 03 · 从一条万能提示词到可审阅的备课工作流

状态：课程草案。对象：反复让 AI 重做课件、却难以保持要求一致的教师与课程设计者。先修：一份有权使用的材料、明确受众与学习任务；会改 Markdown 即可，不强制安装工具。预算 240 分钟。交付：工作流契约、两个输入案例、两版六页课件或纸面稿、审阅与失败记录。

学习目标：读懂 Skill 的触发、输入、步骤和资源依赖；让缺资料时停止猜测；把生成与验收分开；用相同输入比较修订结果。

## 分课与可执行步骤

### 1. 先体验工作流的成品，再回看怎么生成（35 分钟）

前 5 分钟在浏览器打开已有数学课件示例（工作区 library/visual-cognition-slides/examples/01_math_v2.html，公开仓库不附带；无法访问时使用下述 starter），看前两页并操作页面提供的导航，写出一个学生动作和一个想改变的地方。这个本地材料只供体验，不随网站发布；运行表现仍需你实际核对。若示例无法打开，改用[分数练习 starter](starters/fraction-lab.html)，把预测、操作、解释拆成三页纸面课件。到此你已知道想做的成品，再阅读生成工作流。

从 Radar Skills 找一项带 manifest_url 的候选，打开 source_repository 与 skill_path，对照 description 与实际正文。另读 Visual Cognition Slides 的公开 SKILL.md；把触发、参考文档、脚本、安装要求写入证据卡。本课不把外来 Skill 文本作为可信系统命令；先了解会读什么、执行什么。

练习：找一个只从 frontmatter 不能判断的问题，比如是否会安装依赖或上传素材。标注“manifest 已验证”与“行为尚未验证”的区别。

### 2. 写输入与输出契约（45 分钟）

填 `templates/workflow-contract.md`：五年级、10 分钟、同整体分数比较、原创题、离线 HTML/纸面任选。缺受众或目标时只问关键问题；缺来源时使用明确标记的占位符，不虚构研究。输出要求六页：预测、反例、操作、解释、迁移、教师检查；每页写学生动作、材料、反馈、验收。

练习：给一个缺年级的输入，检查工作流是否先澄清；给一个素材许可未知的输入，检查是否转用原创材料。

### 3. 复用一小段工作流（55 分钟）

选 Visual Cognition Slides 的任务设计或 Frontend Slides 的展示流程，明确采用的文件与 commit。保留原 LICENSE；不要将两套全仓库规则堆进一次提示。基线稿先手工写六页，再用已有 AI 助手按契约生成 A 版。无 AI 时让同伴按契约执行也可完成过程练习。若确实复制上游内容，保留其通知与改动说明；模板本身是原创，不包含上游代码。

### 4. 审阅比生成更具体（50 分钟）

逐页核对数学、文字长度、引导顺序、示例、图片来源。检查开头有没有泄露迁移题答案，动效是否遮住阅读，离线时字体和图形是否降级。A 版出现的问题记为规则冲突、输入缺失、知识错误或界面问题；只修改一条工作流规则后生成 B 版。保留同一输入，不能改任务后声称 B 更好。

练习：加入“材料有一处错误等式”的对抗案例，看看工作流能否指出需人工核对而非美化错误。

### 5. 最小回归与交付（40 分钟）

第二个输入换成关系表达任务，检查格式仍成立但数学规则没有误套。保存输入、采用的源文件、版本、A/B、人工检查结果与失败案例。若输出 HTML，实际打开、按键导航、窄屏检查；若只交纸面稿，标明未生成或运行 HTML。

### 6. 同伴可重复执行（15 分钟）

同伴只拿契约与材料能否做出符合要求的稿？记录不明确的一条规则并修订。输出是可检查的过程，不宣称跨代理自动兼容。

## 开源依赖与许可

[Visual Cognition Slides](https://github.com/edu-ai-builders/visual-cognition-slides) 与 [Frontend Slides](https://github.com/zarazhangrui/frontend-slides) 均为 MIT，采用时保存版权与许可。优先走纯 HTML/纸面路线；PPT/PDF 转换会引入额外库和素材许可问题，超出必做范围。[Anthropic Skills](https://github.com/anthropics/skills) 仅作结构参考，不能把整个仓库统称一个许可；webapp-testing 文件明确为 Apache-2.0，部分 document Skills 是 source-available。具体依据见核验台账。

## Rubric（四项各 0–3）

输入契约、步骤与停止条件、内容正确与可用、重复与版本证据。最低 8/12，内容正确≥2；有未解决数学错误不交付学生使用。3 分例：第二种输入不误套第一种规则，且失败记录能解释修订理由。AI 说“已验收”不能充当人工检查。

## 卡点与支持

“Skill 越长越稳”：删掉无关规则，保留输出契约。“模型不读引用文件”：确认实际提供了文件，否则在输入中明确附材料。“页面漂亮但没任务”：每页补学生动作。“工具不支持同一触发命令”：使用正文契约手工执行，不承诺一键跨工具安装。“输出漂移”：记录工具/模型与日期，重跑两例，降低对单次成功的信任。
