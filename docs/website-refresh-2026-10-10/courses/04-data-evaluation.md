# 04 · 让“AI 反馈还不错”变成可复查的证据

状态：课程草案。对象：准备给教育工具接入模型反馈的开发者、能整理题目的教师。先修：能运行 Python 3 或用表格逐行检查；已知道自己要测试什么。预算 300 分钟。交付：数据卡、开发/留出划分、A/B 输出与评测报告；无需付费 API。

学习目标：区分 benchmark 与课堂任务；分开答案正确性、提示泄露、教学适配；保留原始输出；识别样本选择、泄漏和自动指标的盲区。

## 分课与步骤

### 1. 先看到一次失败，再定义要测什么（40 分钟）

前 5 分钟先试[现成分数交互](../../../public/tools/fraction-bars.html)，建立要检查的关系。再到本包 `starters/` 目录运行 `python3 evaluate.py cases.json outputs-a.json`，立即看到 f2、f4、f6 的失败；打开对应输出，指出哪条“看似有帮助的反馈”实际上泄露了答案。无需先下载 benchmark、装评测框架或申请 API。不会终端就并排打开 cases 与 outputs-a，按题号手工比对。

选择“学生尚未作答时，反馈不直接给答案，且数学判断正确”。先写三种错误：算错；说对但提前公布答案；给了无关鼓励。写记录单位为一题一次输出，规定任务阶段与期望结构。用包内 `cases.json` 六条原创人工构造用例观察字段；这些不是学生数据，不是模型实测。

### 2. 判断公共数据能代表什么（45 分钟）

读 GSM8K README 的 question/answer 与 `####` 格式，建立数据卡：语言、来源、题型、答案格式、版本、许可与限制。只需在自有目录下载/读取少量条目，不复制全库到网站。参考 ScienceQA 的多模态问题结构，检查图像来源与独立数据条款，未确认前不再分发图片。两者不自动代表中国课堂的分数解释任务；不能用英文算术分数直接证明中文反馈有效。

练习：从公共题型启发，自己写三条有答案和解析的中文题；记录哪些是原创、哪些是翻译改写。翻译不是自动消除上游权利。

### 3. 建立开发集与留出集（45 分钟）

六例只用于学习评测结构：3 条开发、3 条留出。真实作品至少扩至 20 条（12 开发、8 留出），包含正常、等值、反例、错误前提、提示泄露、格式缺失。先划分，再调整提示，记录内容哈希；同一题翻译或轻微改写放在同一划分。留出答案供评测者使用，不放到产品提示中。样本少时逐条列举，比小数精度很多的百分比诚实。

### 4. 跑通离线基线（60 分钟）

在 starter 目录执行 `python3 evaluate.py cases.json outputs-a.json`，再跑 outputs-b。模拟 A 故意含数学和泄露问题，B 修正部分问题但留一个答错例；不能把 B 报告写成模型性能。本脚本检查结构、预期关系和测试作者标注的禁用字面片段，返回逐题失败。人工再审是否提示有用、是否用同义句绕过检查。

练习：把泄露答案换成同义表达，观察字面匹配为何会漏报。把答案期望写错，观察评测也会“认真地错”；用纸笔复核标准答案。

### 5. 接真实输出或扩展框架（65 分钟）

可选已有模型：将题目与任务阶段给模型，独立保存未经修改的输出；只把结构化结果映射为脚本字段，不能悄悄修答案。记录提示、工具/模型、时间、参数、次数与费用；最多先跑 6 条，预算由学习者自定。没有模型就继续扩展人工输出，用来测试评测器而非性能。

可选 Promptfoo（MIT）：依官方配置文档建立实验，并先用 echo provider 验证断言走通；echo 只回显输入，不能验证模型能力。安装版本记录进报告，课程不固定“latest”作为可复现版本。外部网络、API 密钥和成本不是必需条件。

### 6. 写有边界的结论（45 分钟）

分别报告结构通过、关系正确、字面泄露及人工教学审阅，以题号解释 A/B 差异。开发集改进后只能在未参与调参的留出集上讨论泛化线索。8 条留出仍不足以概括所有课堂；列下一轮需要补的失败。交付数据卡、原始输出、脚本/命令、逐题结果、人工审核与限制。

## 依赖与许可

必做 Python 3 标准库＋原创题与模拟输出。公共资源：[GSM8K](https://github.com/openai/grade-school-math)（仓库 MIT，保留其许可及引用）、[ScienceQA](https://github.com/lupantech/ScienceQA)（仓库 MIT；图片与外部数据单独复查）、[Promptfoo](https://github.com/promptfoo/promptfoo)（MIT；可选）。Radar 的 dataset/benchmark 是启发式形态，可能含索引或工具，不把其 631/321 条直接称高质量数据集。

## Rubric（四项各 0–3）

数据与划分、指标与盲区、可复现与原始输出、结论边界。至少 8/12，划分与结论均≥2。3 分例：发现自动指标漏掉同义泄露，补人工检查，仍保留原来的失败。不得用模拟输出报告真实模型表现；不得用模型正确率替代学生学习效果。

## 卡点

“benchmark 下载太大”：先原创六例。“答案含解析”：GSM8K 最终数值在 `####` 后，先纸笔核对再解析。“判分器给高分”：与明确规则和人工对照，不让同一模型同时决定所有答案与评价。“不支持 JSON”：记录结构失败，映射过程透明。“数字看起来很好”：列分子/分母、失败题与样本选择。
