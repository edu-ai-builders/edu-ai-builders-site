# 01 · 不再收藏一堆用不上的资源：写出复用决策

状态：课程草案。先修：浏览器、文本编辑器；可选 Python 3。对象：教师、课程设计者、第一次接触开源教育工具的人。完成后能说清“它解决我的哪一小步、依据是什么、我准备改哪里”，交出三张证据卡与一页选型说明。预算 180 分钟。

## 分课与可执行步骤

### 1. 先试别人做好的，再找到自己的课堂卡点（30 分钟）

前 5 分钟直接在浏览器打开[已有分数条工具](../../../public/tools/fraction-bars.html)，不用安装也不先读 README。预测 1/2 与 2/4，操作后说出结果；再试 1/3 与 1/4。接着打开[本包练习版](starters/fraction-lab.html)，先选择预测再看图，感受“能演示”和“能组织练习”的区别。写一句想保留的交互、一句想改的引导，即可开始。

接着 10 分钟画出输入→状态→表征→反馈四块，指出哪块是可复用骨架、哪块是需要你负责的教学内容。试用不等于复制源码；到第 3 课再核对具体复用许可。

剩余 15 分钟把体验带回场景，写具体人、材料、动作和失败：“五年级学生比较同一整体的 1/3 与 1/4，能指出每份大小与份数”。列设备、语言、联网、老师可维护时间。把“提升数学能力”改为一项能在 10 分钟观察的行为。填 workbook 需求页；画学生进入页面、作判断、得到反馈、做新题的四格流程。

练习：同一资源分别服务教师投屏与学生手机独立操作，写两项不同约束。验收：说明谁操作、老师何时介入、如何知道页面做错。

### 2. 从 Radar 找三个不同形态的候选（35 分钟）

先在 directory 按自己的问题找一个可体验项目：有 demo 就点开，只完成一个主要动作；没有 demo 就记录运行要求，不以安装完整平台作为入门门槛。接着使用本地 `apps/radar/data/registry.jsonl` 与 `skills.jsonl`，或公开目录。分别找一个应用/系统、一个 Skill、一个数据/benchmark。先按动作与设备筛选，再读原始仓库 README。可比较 Kolibri（平台）、visual-cognition-slides（工作流）、GSM8K（题集）。后两者是本次外部补充，不能写成已在 Radar 收录。

手工路径：搜索 exact owner/repo，记来源与抓取日期。Python 路径：逐行 `json.loads` 后按 full_name 或 description 筛选，打印最多 10 项。不要把候选的分类当深度审查结论。练习：在 registry 中找一个被归为 dataset、实质是资源索引的条目，记录误分类如何改变决策。

### 3. 判断能否复用（50 分钟）

每个候选打开 README、LICENSE、依赖文件及一个关键实现文件；记录访问日期和使用时的 commit SHA。分别写代码、内容、图像、模型/数据权利。缺许可写“未知”；允许阅读不自动等于允许再分发。检查离线行为、安装步骤、最近已解决与未解决问题；这些只是维护线索，不折成星数评分。

必做反例：Math Viz Kit 页面可以公开读，但本次根目录未观察到 LICENSE；练习不得直接宣称可按 MIT 分发。选它做分析参考，或改用包内原创 starter。把至少一个不采用的理由写入证据卡。

### 4. 用一次最小实验结束选型（45 分钟）

从已明确许可的候选选一个最小环节，或使用原创 fraction starter。在自己的目录保存原版与改版；运行后只改一句引导，确认变化。平台候选如 Kolibri 本课只读架构与安装要求，不以一节课“完整部署 LMS”为验收。填 workbook 决策：采用/仅参考/暂缓；选一个撤回条件，如断网时主要动作失效。

### 5. 交付与同伴复核（20 分钟）

请同伴只读选型页：能否找到上游、为什么匹配需求、未知项？补一张“资源证据→教学假设→待验证动作”表，不把 README 的宣传写成结论。交付三证据卡、一决策页、一运行或阅读记录。

## 资源与许可

[Kolibri](https://github.com/learningequality/kolibri)：平台比较对象，MIT 代码；频道材料许可另查。[Visual Cognition Slides](https://github.com/edu-ai-builders/visual-cognition-slides)：MIT，工作流候选。[GSM8K](https://github.com/openai/grade-school-math)：题集分析候选，仓库 LICENSE 为 MIT；具体数据复用记录见台账。包内原创 starter 没有外部代码依赖。

## Rubric（四项各 0–3 分）

0=缺失；1=有说法但无法回溯；2=可检查且符合本情境；3=还提供反例或撤回条件。四项：需求是否可观察；来源与版本是否可追溯；代码/内容许可是否分开；选择是否有最小验证。至少 8/12 且来源、许可均≥2 才进入复用；许可未知的候选可选择“仅参考”，不算失败。

## 卡点与帮助

“搜不到”：先用英文动作词与 exact repo URL，不扩大到全部 AI 项目。“结果太多”：设备/语言先裁切，最多三候选。“NOASSERTION”：是未识别，不是宽松许可。“不会装平台”：交阅读决策与配置预算，先做单 HTML。“仓库打不开”：记录失败，选另一个已核验来源，不编造运行结果。
