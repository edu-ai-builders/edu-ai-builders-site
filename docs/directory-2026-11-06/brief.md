# Edu AI Builders directory consolidation

Decision date: 2026-11-06. This records the user's current direction and supersedes older standalone Radar and separate marketplace display plans.

## Product purpose

Edu AI Builders is the home for a future agent and client that finds, compares, adapts and combines reusable resources for personal learning, teaching, educational research and educational system administration. The directory supplies evidence for that work. It is not limited to classroom apps or trending repositories.

Keep open-source Skills, reusable applications and libraries, datasets, tutor and model-training benchmarks, open textbooks, courses and knowledge graphs across disciplines. Generic building blocks qualify when their reusable role is clear. A repository is a container and may offer several artifacts. Record source verification, reuse conditions and execution evidence separately.

## Ownership

- The canonical collector, configuration and registries live in `radar/` in the Edu AI Builders website repository.
- `apps/radar` is a compatibility symlink to `apps/site-original/radar`, not another copy.
- `/directory` is the single public discovery display. The saved GPT website preview remains separate.
- The source destination is `https://github.com/edu-ai-builders/edu-ai-builders-site.git`. The old Radar repository remains historical; do not delete or force-push it.
- Local refresh and export do not imply a GitHub push or a production deployment.

## Work plan

1. Read the poteto-mode principles and capture the unchanged baseline.
2. Frame completion, scope and evidence.
3. Review discovery phrases, existing resources and taxonomy in three separate agent workstreams.
4. Integrate the collector and one reviewed catalog into the website.
5. Run classification, export, search, build and browser checks.
6. Record decisions and remaining publication limits.

Completion means the actual local `/directory` reads the reviewed canonical catalog, representative current resources can be found, unsupported labels no longer become confirmed capabilities, exclusions have recoverable reasons, and the weekly workflow points at this source and exports to this website.

## Review contract

- Discovery provenance is not proof of artifact type, subject, audience or capability.
- Prefer longer task phrases and varied learning, research, operations and subject coverage over broad isolated words.
- Do not blacklist programming languages or dates. Stale runnable software, stable knowledge resources and inactive benchmarks need different judgments.
- Keep raw metadata and history. Exclude weak, obsolete or irrelevant candidates from public display with a recorded reason; uncertain cases remain reviewable.
- Preserve scoped license observations and original verification dates. Missing evidence is unknown, not success or failure.
- Check exact OpenAI source repositories and the DeepTutor identity against primary sources. Do not invent a trending list or assume popularity establishes suitability.
- Do not clone or execute third-party Skills, download datasets, create paid resources, publish or push as part of this review.

## Throughput checkpoint

Three agents own disjoint outputs. The parent is the only writer of canonical registry rebuilds, website export, task configuration and integration documents. Reuse the existing Python collectors and website UI; add no service, database or new marketplace UI.
