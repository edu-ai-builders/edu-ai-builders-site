# Skill Fusion scope — v0.2.1

2026-10-12 更新。已交付原创 MIT agent skill、融合决策模板、家庭数学 workload 的独立新 skill 与决策记录，以及站内下载入口。包结构、来源证据工具和有限独立任务走查已检查；自动触发与 token 节省尚未评测。

## 要解决的问题

用户有稳定的工作方法，但现有 skills 太宽、重叠或冲突。Fusion 根据用户 workload 重新定义触发条件、流程与交付标准，形成一个有自己版本和来源记录的新 skill。

| 选择 | 何时适用 |
| --- | --- |
| 直接复用 | 一个已有 skill 已符合目标与约束。 |
| Orchestration | 只需要安排现有 skills 的顺序、条件与结果传递。 |
| Fusion | 需要围绕稳定 workload 裁剪、改写、消除冲突，形成自己的方法。 |

融合后的 skill 可以保留专业委派；调用多个 skills 本身不能证明已完成 fusion。

## WorkloadSpec 输入契约

- 触发任务、不适用任务，典型输入输出，至少两个代表性例子。
- 用户方法与偏好；硬约束与可调整偏好；冲突时的优先级。
- 平台、已有工具、可委派 skills，以及工具缺失时的降级方式。
- 学习者、教育目标、提示与反馈、语言、无障碍、资料来源边界。
- 可读与可改范围、上下文预算、停止条件与验收要求。
- 候选 skills 的固定版本、完整相关方法与具体组件使用条件。

目录摘要只用于发现。实际融合须按需读相关完整指令，不能靠 name/description 宣称理解或融合了方法。

## 执行方法

1. 确定复用、编排或融合，保留用户已明确要求的新 skill 目标。
2. 将 workload 收窄到一个可重复任务，列出 requirements 与优先级。
3. 搜索候选，固定版本，按需读相关指令与资料，记录可使用范围。
4. 建立决策表：保留、改写、委派、移到参考资料或删除，每项对应 workload 的理由。
5. 统一输入输出、术语和关键状态，消除重复，显式处理冲突。
6. 按 workload 写新触发条件；写简洁 SKILL.md，长资料按需放入 references。
7. 核对结构、引用、来源与验收；按实际测试记录质量与失败。
8. 建立上游变化 → 新 skill 需要复查的部分的映射。

不复制所有触发词，不默认拼接所有正文，不把更少的入口当成更好的结果。可保留委派，但必须有可用性检查与缺工具的 fallback。

## 输出契约

- WorkloadSpec 与选择 fusion 的理由。
- 独立 SKILL.md：触发、非适用范围、决策、流程、停止与完成条件。
- 必要的 references；脚本只为确有需要的重复机械操作制作。
- Source/version/reuse record 与融合决策表。
- 代表任务、边界任务、应不触发任务与结果记录。
- 上游变更复查关系，版本与更新记录。

包内 `references/fusion-contract.md` 提供交付契约。

## 已制作的真实样例

`packages/builder-skills/examples/family-math-workflow/` 是新生成的家庭数学工作方法：中英双语、移动端优先、先尝试再逐层提示、初版不依赖付费模型。

它从本项目原创 Search 与 Design/Plan 的相关方法提炼而来，来源以文件哈希与版本固定，避免把公共目录的第三方摘要误当作完整融合。决策记录包含保留、改写、删除、专业委派与上游复查关系。PDF 方法在具备工具且确有材料导入需求时委派；工具缺失时先用可人工检查的题目。模型训练被移出该 workload。

已交付新 skill 和验收案例；没有执行多模型/多 agent 对照实验。示例下载 `family-math-workflow-example.zip`。

## 验收与评测

- 常规任务：双语家庭数学练习，检查提示顺序和来源记录。
- 边界任务：PDF 工具缺席，仍能产出有限的最小计划并标出缺口。
- 不适用任务：模型训练请求，不能扩张本 skill 的职责。
- 上游更新：相关方法变化可追溯到新 skill 的哪一部分需要复查。

质量优先检查需求符合、结果可用、返工与错误；对比原编排时记录同模型、同任务与实际返回的 token/耗时。当前不宣称节省百分比。

## 分发与维护边界

本项目原创包为 MIT。未知许可或仅浏览授权的第三方内容应保留链接、专业委派或独立创作，不能默认再分发。生成新包不等于自动安装；也不会改变用户当前 agent 的配置。

目录/API/MCP 提供发现与计划资料。Fusion 由用户自己的 agent 按指令执行，网站当前没有托管模型融合服务。维护订阅未来可覆盖 workload 版本、来源变化与验收复查，当前尚未收费。

## v0.2.1 迭代交付

完整指令入口、按需参考资料、机器可读模板、无第三方依赖的 Python 证据工具与 Codex UI metadata 已加入。保留自动发现，不依赖另装第三方 skill。测试数据、独立任务产物与回归测试保留在 `tests/skill-evals/`；脚本测试不等同于 agent 任务或教学效果评测。

`fusion_provenance.py` 核对来源哈希、融合决策、目标文件、要求 ID、委派降级和上游复查映射。摘要或未知许可的方法不能被标为已读且可再分发。独立测试分别覆盖新 workload、只要编排、缺工具、不适用任务和互斥硬要求；生成方法的备用分支也须遵守同一组硬约束。

最新任务与实际结果见 [迭代验证报告](skill-iterations-2026-10-12.md)。此前的未评测状态是 v0.1.0 的历史记录；这轮完成有限本地测试，不宣称跨模型性能提升。
